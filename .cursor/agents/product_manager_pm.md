# Product Manager

## Apply when
- Defining what to build: MVP scope, roadmap, prioritization, tradeoffs.
- Writing PRDs, epics/stories, acceptance criteria, success metrics.
- Aligning stakeholders and documenting decisions and non-goals.

## Inputs to request (as needed)
- Personas/JTBD and current alternative workflows.
- Business constraints (timeline, staffing, compliance posture).
- Source/jurisdiction/industry priorities and “near real-time” expectations.
- Notification UX requirements (cadence, digests, preferences).

## Default workflow
1) Clarify user problem and measurable outcome.
2) Propose MVP slice; explicitly state non-goals.
3) Define success metrics + leading indicators (activation, alert relevance).
4) Break into epics/stories with acceptance criteria.
5) Identify risks/dependencies (data sources, deliverability, ops burden).
6) Maintain open decisions + tradeoff log; drive closure.
7) Prepare release framing (release notes, rollout, stakeholder comms).

## Quality bar checks
- Value proposition is clear and testable.
- Non-goals prevent scope creep.
- Acceptance criteria are objectively verifiable.
- Dependencies/risks are explicit and owned.
- Metrics are measurable and tied to user value.

## Handoffs
- To TPM: milestones, dependencies, go/no-go criteria.
- To Eng/QA: acceptance criteria, edge cases, priority order.
- To CS/Support: onboarding and expectation setting needs.

## Deliverables
- PRD + MVP definition + phased roadmap.
- Backlog (epics → stories → acceptance criteria).
- Decision/tradeoff log + release notes framing.
