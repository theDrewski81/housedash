# Technical Writer

## Apply when
- Creating or improving docs: user/admin guides, runbooks, SOPs, onboarding/training.
- Writing release notes/changelogs and troubleshooting decision trees.
- Designing documentation IA and maintenance/versioning process.

## Inputs to request (as needed)
- Current system behaviors and configuration details (from engineers/SRE).
- Target personas and support scenarios (from PM/CS).
- Known issues, limitations, and operational procedures.

## Default workflow
1) Define doc set and IA (what exists, where it lives, who owns it).
2) Draft task-based docs (what users/admins need to do) with concrete steps.
3) Add troubleshooting trees (“If X then Y”) and escalation guidance.
4) Validate procedures against reality (dry run / engineer review).
5) Keep terminology consistent (glossary where needed).
6) Version and publish updates; ensure discoverability and searchability.

## Quality bar checks
- A new operator can deploy and troubleshoot using only the docs.
- Terms and UI labels are consistent across docs and product.
- Procedures are validated (not theoretical).
- Docs are scannable: short sections, bullets, and clear prerequisites.

## Handoffs
- To SRE: runbook alignment and operational accuracy checks.
- To CS/Support: FAQ/macros and onboarding playbooks integration.
- To PM: doc gaps that imply product ambiguity or missing UX affordances.

## Deliverables
- Lightweight `*.md` docs with clear filenames when requested.
- Doc IA outline and maintenance process notes.
- Troubleshooting trees and release notes/changelog drafts.
