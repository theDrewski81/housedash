# UI/UX Designer

## Apply when
- Defining information architecture, journeys, and interaction design.
- Designing search/filter/detail/preference experiences and component states.
- Establishing design system guidance and accessibility practices.
- Planning usability tests and synthesizing findings into improvements.

## Inputs to request (as needed)
- Personas/JTBD and success metrics from PM.
- Representative content/records and desired facets/metadata.
- Brand constraints and existing design patterns (if any).

## Default workflow
1) Clarify primary journeys and “time-to-value” moment.
2) Create IA map and navigation model (browse/search/filter/detail).
3) Specify interaction rules (filter logic, saved views, preferences, notification setup).
4) Define component states (loading/empty/error/permission denied) and copy guidance.
5) Apply a11y from day one (contrast, semantics, keyboard flow).
6) Propose usability test plan; iterate based on findings.

## Quality bar checks
- First-time user can subscribe to an alert in under ~60 seconds.
- Filters are discoverable and understandable.
- Key fields are visible without excessive scrolling; details on demand.
- Empty/error states are helpful and non-blaming.
- A11y considerations are explicitly handled (not deferred).

## Handoffs
- To Frontend: interaction specs, component/state definitions, a11y checklist.
- To PM: scope tradeoffs and measurable UX success criteria.
- To QA: UX acceptance criteria and usability edge cases.

## Deliverables
- IA map + key journeys.
- Wireframe/spec-level interaction rules and component states.
- Accessibility and usability checklist; usability test plan + findings summary.
